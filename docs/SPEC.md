# Спецификация движка

## 1. Цели и не-цели

**Цели**
- Оживлять готовое ASCII-полотно, полученное из изображения или текста.
- Эффекты как параметризуемые функции-пресеты, которые можно комбинировать в цепочку, сохранять и загружать в JSON.
- 2D, но выразительно: искажения, частицы, следы, интерактивность курсором.
- 60 fps на полотне до ~200×100 ячеек на среднем ноутбуке.

**Не-цели (пока)**
- 3D, WebGL-рендер (интерфейс рендера должен позволить добавить его позже).
- Генеративные программы без исходника (как в aiscii) — возможны как частный случай, но не цель.
- Экспорт видео (возможен в последней фазе).

## 2. Модель данных: Field

```ts
export type Polarity = 'light-on-dark' | 'dark-on-light';

export interface Field {
  readonly cols: number;
  readonly rows: number;
  lum: Float32Array;               // 0..1, яркость изображения (0 = чёрный)
  alpha: Float32Array;             // 0..1, 0 = фон/пустота
  color: Uint8ClampedArray | null; // RGB чернил символа, length = cols*rows*3 (DECISIONS 015)
  char: Uint16Array | null;        // авторские символы (charCode), 0 = нет
  gradX: Float32Array | null;      // Sobel по lum, считается при импорте
  gradY: Float32Array | null;
}

export interface FieldMeta {
  cellAspect: number;              // ширина/высота ячейки, ~0.5–0.6
  polarity: Polarity;
}
```

Индексация: `i = y * cols + x`. Источник (`source`) после импорта не меняется. Каждый кадр движок копирует его в рабочий буфер (`work`), который и модифицируют эффекты. Буферы выделяются один раз и переиспользуются; при смене размера — пересоздаются.

Рабочий буфер дополнительно содержит:
- `charOverride: Uint16Array` — символ, выставленный эффектом (0 = нет, выбирать по рампе);
- `hidden: Uint8Array` — 1 = ячейку в этом кадре рисует спрайт, в сетке она пустая (данные ячейки остаются для спрайта);
- `sprites: SpritePool` — пул свободно позиционированных глифов (`x`, `y` в ячейках, левый верхний угол ячейки — целые; `src` — ячейка-источник; `alpha`; `count`), ёмкость = число ячеек (см. §6.3).

## 3. Импорт

### 3.1 Изображение → Field

Параметры импорта: `cols`, `cellAspect`, `brightness`, `contrast`, `gamma`, `invert`, `bgThreshold` (опционально), `rows` и `place` (опционально, DECISIONS 022).

1. Загрузить в `ImageBitmap`; пиксели читаются один раз (`readPixels`, длинная сторона до 2048).
2. `rows` — из холста (`round(cols · H/W · cellAspect)`) или, при холсте `auto`, из картинки: `round(cols * (imgH / imgW) * cellAspect)`.
3. Картинка раскладывается в сетку по `Placement` (`fit` cover/contain/stretch, `x`/`y` 0..1, `zoom` 1–4; `placeInGrid`, изотропно). Даунскейл с усреднением по площади (не nearest); ячейка вне картинки — `alpha` 0, частично покрытая — `alpha` по доле покрытия.
4. `lum` = Rec.709 по sRGB-значениям (`0.2126 R + 0.7152 G + 0.0722 B`), затем levels: brightness / contrast / gamma, clamp 0..1.
5. `alpha` — из альфа-канала изображения. Если задан `bgThreshold`, вычисляется `cornerLum` — среднее `lum` четырёх угловых ячеек; ячейка получает `alpha = 0`, если `|lum - cornerLum| < bgThreshold`. Сравнение идёт по яркости, а не по RGB: `color` опционален и при импорте может отсутствовать.
6. `color` — средний RGB ячейки (опционально, флаг импорта).
7. `gradX/gradY` — оператор Собеля по `lum`.

### 3.2 Текст → Field

1. Нормализовать переводы строк в `\n`, табы в пробелы.
2. Разбить строки на графемы (`Intl.Segmenter`); одна графема = одна ячейка. Графемы длиннее одного code unit, широкие и одиночные комбинируемые/нулевой ширины символы заменить пробелом с предупреждением в консоль (список символов). См. DECISIONS 009.
3. Дополнить строки пробелами до максимальной длины (в графемах).
4. `char` = исходные символы.
5. `lum` — обратный поиск символа в рампе: плотность символа, затем учесть полярность (обратить, если `dark-on-light`). Символ не из рампы → измерить его обязательным параметром `measure: DensityMeasurer` (тот же механизм, что у `measureRamp`) и перевести на шкалу рампы через `normalizeDensity` (DECISIONS 008, 011). Импорт текста — вторая (вместе с квантователем) и последняя точка, где полярность имеет значение; см. инвариант 3 в `AGENTS.md`.
6. `alpha = 0` для пробелов, иначе 1.
7. Градиент — как в 3.1.

## 4. Рампа

```ts
export interface Ramp {
  chars: string;          // отсортировано по возрастанию плотности
  density: Float32Array;  // измеренная плотность каждого символа, нормирована 0..1
  rawMin: number;         // сырые плотности, ставшие 0 и 1 (DECISIONS 011)
  rawMax: number;
}

export type DensityMeasurer = (char: string) => number; // сырое покрытие 0..1
```

Сборка рампы разделена на две функции:

- `makeRamp(chars, density)` — чистая: отбрасывает дубликаты символов, сортирует пары (символ, плотность) по возрастанию плотности, нормирует плотности в 0..1 (min-max). Вся логика, которую можно проверить тестом, живёт здесь.
- `createDensityMeasurer(font)` — canvas-измеритель для шрифта, кэш по шрифту и символу. Размер ячейки в `font` — физические пиксели, тот же тайл, что рисует атлас; шрифт настраивается общей с атласом функцией `setupGlyphFont`.
- `normalizeDensity(ramp, raw)` — переводит сырую плотность на шкалу рампы с клампом в 0..1.
- `measureRamp(chars, font)` — рисует каждый символ на offscreen canvas размера ячейки, считает долю закрашенных пикселей (по альфе) и возвращает `makeRamp(chars, measured)`. Требует DOM, тестами не покрывается. Результат кэшируется по (chars, font). Плотность блочных символов (§9.3) берётся аналитически, а не измеряется.

Свойства `Ramp`:

- `chars` — всегда результат сортировки по измеренной плотности, а не входная строка: входная строка задаёт только *набор* символов. Порядок встроенных рамп подобран руками и обычно совпадает с измеренным, но расхождение — не ошибка.
- `density` нормируется min-max, то есть самый плотный символ рампы получает 1.0, самый пустой — 0.0, независимо от их физического покрытия. Иначе светлая часть диапазона яркости не отображалась бы ни на один символ (см. DECISIONS 006).
- Degenerate-случаи: рампа из одного символа — `density = [0]`; все плотности равны — все нули (нормировка не делит на ноль). Пустая строка — ошибка.

Квантование: `ink = polarity === 'light-on-dark' ? lum : 1 - lum`, затем выбор символа с ближайшей плотностью к `ink` (бинарный поиск по `density`). Это лучше равномерного `round(ink * (n - 1))`, потому что учитывает реальную неравномерность плотностей. Режим `uniform` оставить как опцию.

- Встроенные рампы: `blocks` (` ░▒▓█`), `classic` (` .:-=+*#%@`), `long` (~70 символов), `binary` (` 01`), `dots` (` .·•●`). Блочные символы рисуются процедурно (§9.3), их плотность задаётся аналитически.
- Рампа — глобальная настройка; переопределение рампы эффектом в маске — фаза 6.

## 5. Контекст кадра

```ts
export interface Pointer {
  x: number; y: number;     // в ячейках, дробные
  vx: number; vy: number;   // скорость, ячеек/с, сглаженная
  inside: boolean;
  down: boolean;
  clicked: boolean;         // true ровно в кадре нажатия
}

export interface FrameContext {
  time: number;             // секунды с начала
  dt: number;               // секунды, clamp до 1/20
  frame: number;
  cols: number; rows: number;
  cellAspect: number;
  pointer: Pointer;
  rand: () => number;       // сидированный PRNG, детерминированный
  source: Readonly<Field>;
}
```

Утилиты в `core/sample.ts`:
- `sampleLum(field, x, y)` — билинейно, координаты дробные, за краем — clamp (режим `wrap` опционален).
- `sampleAlpha`, `sampleColor` — аналогично.
- `distIso(dx, dy, cellAspect)` — расстояние с поправкой на соотношение сторон ячейки.

## 6. Эффекты

Общий дескриптор:

```ts
export type EffectKind = 'displace' | 'cell' | 'system';

export interface EffectDef<P extends Record<string, ParamSpec>> {
  id: string;               // 'ripple'
  name: string;             // 'Ripple'
  kind: EffectKind;
  params: P;
  create(params: ResolvedParams<P>): EffectInstance;
}
```

Эффект объявляется через `defineEffect(def)`: внутри типизирован по своей схеме (`const`-дженерик, литералы `select` выводятся без `as const`), в реестр и цепочку попадает стёртый `AnyEffectDef`. При смене источника и при `restart()` все экземпляры пересоздаются вызовом `create` — состояние эффекта живёт в замыкании и начинается заново вместе с картинкой (DECISIONS 012).

`params` в `create` — живой объект, который движок обновляет каждый кадр (значения уже разрешены из LFO и огибающих). Замыкания эффекта просто читают `params.speed`.

### 6.1 Displace

```ts
export interface Vec2 { x: number; y: number }
export type DisplaceFn = (x: number, y: number, ctx: FrameContext, out: Vec2) => void;
```

- `out` на входе содержит текущие координаты выборки (изначально `x, y` ячейки); функция их модифицирует. Цепочка displace-эффектов композиционна: каждый следующий получает результат предыдущего.
- После всех displace-эффектов движок делает выборку из `source` билинейно (`lum`, `alpha`, `color`) в рабочий буфер. Авторские `char` при смещении берутся nearest. Выборка за краем прижимается к краю (clamp). Без включённых displace-эффектов стадия — обычная копия source → work.
- Эффект может считать своё поле смещений на грубой решётке раз в кадр (по смене `ctx.frame`) и интерполировать его в текущей точке `out` — так делает `liquid`. Композиция цепочки при этом сохраняется.

### 6.2 Cell

```ts
export interface CellRef {
  lum: number; alpha: number;
  r: number; g: number; b: number;
  char: number;             // 0 = выбрать по рампе
}
export type CellFn = (cell: CellRef, x: number, y: number, ctx: FrameContext) => void;
```

`CellRef.char` — это `charOverride` ячейки (0 = выбрать по рампе или взять авторский). Авторский `char` эффектам не виден и не меняется. Движок использует один переиспользуемый `CellRef`: читает ячейку из буфера, вызывает по очереди все cell-функции, записывает обратно.

### 6.2.1 Цвет и стадия post

- Режим раскраски (`ColorSettings`: `mode` = `mono` | `source` | `gradient`, `stops` для градиента) — глобальная настройка вида, как рампа и полярность; хранится в пресете. `Pipeline.setColor(settings, ink)`, где `ink` — цвет чернил темы.
- Стадия `post` после cell: `colorize` пишет базовый цвет (`mono` — `ink`; `source` — цвета исходника, для бесцветного — `ink`; `gradient` — LUT на 256 значений по `lum` после cell-эффектов), затем выполняются cell-эффекты с `writesColor: true` — с теми же `mix` и масками, в порядке цепочки (DECISIONS 016).
- Канал `work.color` существует, только если режим не `mono` или включён красящий эффект; иначе `null`.
- `CellRef.r, g, b` — 0..255. Красящий эффект обязан объявить `writesColor`, иначе его цвет перезапишет раскраска. Изменение `lum` в стадии `post` цвет уже не меняет.
- Плашки (DECISIONS 021): `color.plates = { mode: 'none' | 'source' | 'gradient' | 'ink', opacity }`; канал `work.plate` (RGBA на ячейку) по требованию; в `post` после раскраски заполняются плашки (`alpha = opacity · alpha ячейки`), затем эффекты `writesColor` / `writesPlate` (`CellRef.pr, pg, pb, pa`, 0..255). Эффект, пишущий плашку, объявляет `writesPlate`.

### 6.3 System

```ts
export interface SystemInstance {
  step(ctx: FrameContext, work: WorkBuffer, mask: Float32Array | null, mix: number): void;
}
```

DECISIONS 024.
- Системы с состоянием: частицы, следы, осыпание. Стадия идёт после cell и до post (раскраски): `hidden` и `sprites.count` обнуляются каждый кадр, затем системы шагают по порядку цепочки. `mix = 0` — система не шагает.
- Система настраивается на первом шаге (и при смене размера сетки); `restart` и смена источника пересоздают экземпляр.
- Пишут либо в сетку (`work.lum` и т. д.), либо в `work.hidden` + `work.sprites`. Спрайт показывает символ и цвет своей ячейки-источника **в этом кадре** (после post: раскраска, красящие эффекты), поэтому летящий кусок продолжает анимироваться. Плашки со спрайтами не летают: у скрытой ячейки плашка тоже скрыта.
- Физика — фиксированными подшагами (1/120 с) с переносом остатка между кадрами: движение одинаково при любой частоте кадров, на экране и в офлайн-рендере. Триггеры (клик, удар) — по кадрам.
- `mask` — где система действует (участвуют ячейки с весом маски > 0; для частиц — сила толчка × вес).
- Рендер (`render/sprite-layer.ts`): отдельный прозрачный слой размером со слой символов, поверх него (`paintFrame`). Каждый кадр очищается и перерисовывается только прямоугольник, где спрайты были и есть; выгружается он же. Положение — до пикселя (`round(x·cellW)`); перекрытия — точная альфа «over» и цвет более плотного глифа. Нет спрайтов — слой ничего не стоит.
- Экспорт текста: скрытые ячейки — пробел, спрайты — в ближайшей ячейке (позже по порядку — сверху).

### 6.4 Маска и смешивание

У каждого экземпляра эффекта в цепочке:
- `enabled: boolean`;
- `mix: ParamValue` (0..1, может быть LFO);
- `mask?: MaskSpec`:

```ts
export type MaskSpec =
  | { type: 'alpha'; invert?: boolean }
  | { type: 'lum'; min: number; max: number; soft?: number; invert?: boolean }
  | { type: 'radial'; center: PointValue; radius: ParamValue; soft?: number; invert?: boolean }
  | { type: 'rect'; x: number; y: number; w: number; h: number; soft?: number; invert?: boolean };
```

- Единицы маски: `alpha` и `lum` — по исходнику в точке ячейки (не по результату предыдущих эффектов), `min/max/soft` в единицах яркости; `radial` — `radius` (может модулироваться) и `soft` в ширинах ячейки, изотропно; `rect` — `x, y, w, h` нормированы к сетке как точки, `soft` в ширинах ячейки, край затухает внутрь.
- Маска считается раз в кадр в буфер эффекта (`fillMask`), стадии читают только `mask[i]`. Вес `w = mix · mask`: при `w ≤ 0` эффект для ячейки не вызывается, при `w ≥ 1` — вызывается без смешивания.
- Cell: `result = lerp(before, after, mix * mask)` по числовым полям, включая `r, g, b` (DECISIONS 015); `char` применяется, если `mix * mask > 0.5`.
- Displace: смещение `(out - in)` масштабируется на `mix * mask`.
- System: маска передаётся в систему как подсказка (используется по усмотрению системы).

## 7. Параметры

```ts
export type ParamSpec =
  | { type: 'number'; min: number; max: number; step?: number; default: number; label?: string; random?: [number, number] }
  | { type: 'boolean'; default: boolean; label?: string }
  | { type: 'select'; options: readonly string[]; default: string; label?: string }
  | { type: 'color'; default: string; label?: string }
  | { type: 'point'; default: PointValue; label?: string };

export type PointValue = { x: number; y: number } | 'pointer' | 'center'; // x, y нормированы 0..1

export type ParamValue =
  | number
  | { lfo: 'sine' | 'triangle' | 'saw' | 'square' | 'noise'; freq: number; min: number; max: number; phase?: number }
  | { env: Array<[t: number, v: number]>; loop?: boolean; ease?: 'linear' | 'smooth' };
```

- `pipeline/params.ts` разрешает `ParamValue → number` каждый кадр. Часы модуляции — секунды с активации эффекта (добавление в цепочку, включение, `restart`, смена источника); это касается и `env`, и `lfo`, поэтому эффект с одинаковыми параметрами всегда стартует одинаково.
- Объектные значения разрешает реестр источников модуляции (`pipeline/modulation.ts`): значение обрабатывает первый источник, чей ключ-маркер (`lfo`, `env`, в фазе 4.5 — `midi`) есть в объекте. Новый источник — `registerModSource({ key, resolve })`; панель, пресеты и эффекты при этом не меняются. Неразрешимое значение → default.
- LFO: все формы начинаются с минимума при фазе 0 (`sine` = 0.5 − 0.5·cos), `phase` — доля периода. `noise` — сглаженный value noise: новый случайный уровень каждый период.
- Огибающая: точки отсортированы по времени; до первой и после последней — удержание крайнего значения; `loop` повторяет участок между первой и последней точкой; `smooth` — smoothstep между соседними точками.
- Значения за пределами `min/max` схемы клампятся при разрешении.
- Точка разрешается в ячейки: `'center'` → центр сетки `((cols-1)/2, (rows-1)/2)`, нормированная `{x, y}` → `(x·(cols-1), y·(rows-1))`, то есть 0 и 1 — центры крайних ячеек; `'pointer'` — координаты курсора. Разрешение каждый кадр мутирует один и тот же `Vec2`, без аллокаций.
- Неверный тип значения → default (полная валидация с предупреждениями — в пресетах, фаза 4).
- `random?: [min, max]` у числового параметра — диапазон для генератора случайных цепочек (`presets/random.ts`); на разрешение значений не влияет. Без подсказки генератор берёт полосу ±15% размаха вокруг default.
- `ResolvedParams<P>` — отображение схемы в обычные TS-типы (`number`, `boolean`, `string`, `{ x, y }` в ячейках), выводится из `P` на уровне типов.

### 7.1 Точки: позиции и движение (DECISIONS 018)

Режимы точечного параметра (и центра радиальной маски):

```ts
export type PointValue =
  | 'center' | 'pointer'                                   // как сейчас, остаются валидными
  | { x: number; y: number }                               // позиция, x, y ∈ [−0.5, 1.5]
  | { axes: { x: ParamValue; y: ParamValue } }             // по осям: const / lfo / env на каждой
  | { path: PathSpec }                                     // траектория: orbit | lissajous | wander | sweep | bounce | path
  | { follow: 'pointer'; idle?: PathSpec | { x: number; y: number }; ease?: number };
```

- **Позиция.** Доли картинки, 0 и 1 — центры крайних ячеек, допускается −0.5…1.5 (центр за краем даёт дуги вместо кругов). В панели — сетка 3×3 (0 / 0.5 / 1 по осям) и ползунки `x`, `y`.
- **По осям.** Каждая ось — обычный `ParamValue` в долях картинки, разрешается источниками модуляции (§7). Ограничение: две синусоиды дают эллипс на неквадратной картинке — для кругов есть траектории.
- **Траектория** (`PathSpec`, реестр источников точки по образцу модуляции чисел): `orbit` (центр, радиус, скорость, направление, фаза), `lissajous` (частоты по осям, фаза), `wander` (плавное блуждание на шуме), `sweep` (из A в B: пила или туда-обратно), `bounce` (отскоки от краёв), `path` (ключевые кадры `[t, x, y]`, `loop`, `ease`). Считаются изотропно: позиции нормированы как у точки, размеры (`radius`, `rx`, `ry`) и скорость `bounce` — в **долях ширины картинки**, вертикаль пересчитывается через `cellAspect` — круг на экране остаётся кругом при любых `cols`. Частоты и скорости вращения — в оборотах (циклах) в секунду.
- **Курсор с автоматикой.** `follow: 'pointer'` с необязательным `idle`: пока курсор на холсте — точка следует за ним; когда его нет — движется по `idle` (или стоит в последней позиции, если `idle` не задан). Переходы сглажены (`ease`, секунды). Автоматика включается только явно поверх курсора; `'pointer'` без `idle` ведёт себя как сейчас, встроенные пресеты с `'pointer'` не переводятся.
- Часы движения — те же, что у модуляции (секунды с активации эффекта), поэтому офлайн-рендер повторяет движение кадр в кадр, а одинаковые траектории у разных эффектов синхронны.
- Разрешение по-прежнему мутирует один `Vec2` на параметр, без аллокаций. Будущий источник — X/Y-пэд MIDI (фаза 4.5).
- Отладка: в режиме `debug` текущие центры эффектов рисуются на оверлее.

### 7.2 Звук как источник модуляции (DECISIONS 023)

```ts
export type AudioBand = 'level' | 'bass' | 'mid' | 'high';
// В ParamValue добавляется:
//   { audio: AudioBand; min: number; max: number; gain?: number; attack?: number; release?: number }
```

- **Трек** — настройка сессии (как картинка-подложка): файл, раскодированный браузером (`decodeAudioData`), сдвиг начала `offset` (с), `loop`. В пресете не хранится; привязки параметров `audio` — хранятся.
- **Таблица полос** (`audio/bands.ts`). При загрузке трек сводится в моно и проходит своим БПФ (`core/fft.ts`, окно Ханна 2048, шаг 10 мс; окно заканчивается в момент записи — громкость «до сейчас»). На каждый шаг — энергия полос: `level` (средний квадрат сигнала), `bass` 20–150 Гц, `mid` 150–2000 Гц, `high` 2000–16000 Гц, в дБ, нормированная по треку: 10-й перцентиль → 0, 95-й → 1 (диапазон не уже 6 дБ). Результат — `Float32Array` на полосу и префиксные суммы. Анализ идёт порциями с уступкой странице (~1 с на 3 минуты).
- **Разрешение** `audio` в момент `t` (время трека = `offset` + часы транспорта): чтение таблицы с интерполяцией; `gain` — множитель до клампа 0..1; `attack` (0.02 с) — среднее за окно перед `t` (префиксные суммы, O(1)), `release` (0.25 с) — пиковое удержание с экспоненциальным спадом по таблице за последние 4·`release` (не больше 400 шагов). Источник читает часы транспорта и трек из `ModEnv` — своего у каждого pipeline; pipeline делает его текущим перед разрешением параметров (`setModEnv`), поэтому живой вид и офлайн-рендер не мешают друг другу. Без состояния между кадрами: значение зависит только от `t`, поэтому экран, шаг по кадрам, перемотка и офлайн-рендер дают одно и то же. Без аллокаций в кадре.
- Без трека, до начала и после конца (без `loop`) — `min`.
- `AnalyserNode` не используется: его сглаживание зависит от частоты кадров и не повторяется офлайн.
- **Удары** (`findOnsets`): рост громкости полос за 2 шага (20 мс) с весами бас 1, середина 0.6, верх 0.4; удар — локальный максимум (±50 мс) выше скользящего среднего за ±0.25 с плюс 0.08, не чаще раза в 0.12 с; сила — превышение порога, нормированное по 90-му перцентилю, 0..1. Время удара — начало подъёма. Таблица ударов считается при загрузке вместе с полосами.
- **Триггеры.** `FrameContext.beat` — сила самого сильного удара в услышанном за кадр участке трека `(t − dt, t]` (с учётом `offset` и `loop`, `forEachHeard`), иначе 0; один кадр. Пользователи: `ripple` в режиме `beat` (кольцо из `center`, амплитуда × сила) и огибающая с `on: 'beat'` — её время отсчитывается от последнего удара (без состояния, по таблице); до первого удара и без трека — значение последней точки. Механизм общий с будущими нотами MIDI (фаза 4.5).

## 8. Пресеты

```json
{
  "version": 1,
  "name": "Liquid portrait",
  "ramp": "classic",
  "polarity": "light-on-dark",
  "chain": [
    { "effect": "decode", "params": { "duration": 2.5 }, "mask": { "type": "alpha" } },
    {
      "effect": "ripple",
      "params": {
        "center": "pointer",
        "amplitude": { "lfo": "sine", "freq": 0.2, "min": 0.5, "max": 2 }
      },
      "mix": 1
    },
    { "effect": "trails", "params": { "decay": 0.9 } }
  ]
}
```

- `color.plates` — плашки (см. §6.2.1); сохраняются только если не `none`; `stops` сохраняются, если градиент нужен символам или плашкам.
- `backdrop` — фон под символами (DECISIONS 020): `{ kind: 'theme' }`, `{ kind: 'color', color: '#hex' }`, `{ kind: 'transparent' }` или `{ kind: 'image', origin: 'picture' | 'custom', fit: 'grid' | 'cover' | 'contain' | 'stretch', opacity: 0..1, dim: 0..1, blur: 0..0.05 }` (`blur` — доля ширины кадра). По умолчанию `theme`, тогда при сохранении опускается. Сама картинка в пресете не хранится: `picture` — исходное фото, `custom` — файл, загруженный в сессии; без картинки — цвет темы. Кадрирование фона (`x`/`y`/`zoom`), холст и кадрирование исходника — настройки сессии, в пресет не попадают (DECISIONS 022).
- Поля верхнего уровня: `version` (1), `name`, `ramp`, `polarity`, `color: { mode: 'mono' | 'source' | 'gradient', stops?: [{ pos: 0..1, color: '#hex' }] }` (1–8 точек; сохраняются только в режиме `gradient`; отсутствующий блок = `mono`, неверные точки — градиент по умолчанию с предупреждением), `chain`.
- Элемент цепочки: `effect`, `params`, `enabled` (по умолчанию `true`), `mix` (`ParamValue`, по умолчанию 1), `mask` (`MaskSpec`, по умолчанию нет). При сохранении поля со значением по умолчанию опускаются.
- Валидация при загрузке (`presets/preset.ts`): неизвестный эффект → пропустить с предупреждением; неизвестный параметр → игнор без предупреждения; отсутствующий → default; неверный тип → default с предупреждением. Числовой параметр принимается, если это число или объект, который разрешает зарегистрированный источник модуляции. Неверные `ramp`, `polarity`, `mix`, `mask`, `enabled`, `version` → значение по умолчанию с предупреждением; невалидный JSON → пустой пресет с предупреждением. Загрузка пресета никогда не бросает исключение наружу.
- Применение (`applyChain`) заменяет цепочку pipeline и копирует значения: правки в панели не меняют объект пресета.
- Сохранение: текущая цепочка сериализуется обратно в этот формат (скачивание JSON).
- Встроенные пресеты лежат в `src/presets/*.json` и импортируются статически.

## 9. Рендер

```ts
export interface Renderer {
  resize(cols: number, rows: number, cellAspect: number, frame?: { width: number; height: number } | null): void;
  render(work: WorkBuffer, ramp: Ramp, meta: FieldMeta): void;
  dispose(): void;
}
```

### 9.1 Canvas 2D

- Размер ячейки — целые физические пиксели (`fitCell`): самая крупная ячейка, влезающая в контейнер, у которой `w/h` отличается от `cellAspect` не больше чем на 2%. CSS-размер canvas = физический / `devicePixelRatio`. С фиксированным холстом (DECISIONS 022) canvas — кадр в его пропорциях, вписанный в контейнер (`fitFrame`); сетка заполняет кадр целиком (`fillFrame`: целые ячейки, ближайшие к `W/cols × H/rows`, слой символов масштабируется до кадра на несколько процентов) — так же в офлайн-рендере и PNG; курсор и оверлей центров учитывают смещение сетки (`gridRect`). Тема (фон и цвет символов) выбирается по полярности.
- Два слоя (DECISIONS 020). `Compositor` пишет **слой символов** в RGBA-буфер (`ImageData`): пиксель = цвет чернил ячейки с альфой `coverage · alphaScale` (`alpha` ячейки квантуется до 64 уровней), пустые пиксели полностью прозрачны (0). Слой уходит в отдельный холст одним `putImageData` — только полосой строк, где что-то изменилось. Кадр собирается `paintFrame`: фон (`Backdrop`: цвет темы, свой цвет, прозрачный; в шаге 3 — картинка), поверх — `drawImage` слоя. Смешивает браузер; композитор попиксельно с фоном не смешивает.
- Ячейка перерисовывается, только если изменились её символ, квантованная `alpha` или цвет (с допуском 3 бита на канал); смена чернил темы или размера перерисовывает всё; кадр пересобирается, если изменился слой или фон.
- Статичная часть кадра (заливка или подготовленная картинка: вписывание `fitRect`, непрозрачность поверх цвета темы, размытие с обрезкой по прямоугольнику картинки, затемнение) рисуется `prepareBackdrop` в отдельный холст размером с кадр — только при смене фона, картинки, темы или размера. `grid` кладёт картинку туда, где лежит исходник (`pictureRect`: положение исходника в сетке → пиксели кадра), поэтому «исходное фото как фон» совпадает с символами при любом кадрировании. `cover` / `contain` / `stretch` кадрируются своим `Crop` (`x`/`y`/`zoom`, сессия).
- Путь с плашками: пиксель = символ поверх плашки (прямая альфа), пустые пиксели ячейки — плашка; палитра на 33 уровня на перерисованную ячейку, веса из таблицы по альфе плашки; ключ изменения включает плашку (5 бит на канал цвета, 4 бита альфы).
- Монохромный путь — палитра «чернила темы × 256 уровней альфы», цветной — `rgb ячейки | (альфа << 24)` на пиксель.
- Холст кадра всегда чётного размера (H.264), полоса дополнения — фон. При прозрачном фоне на экране под холстом шахматка (только CSS, в экспорт не попадает).
- Экспорт кадра: `save PNG` — итоговый кадр с фоном, прозрачный там, где прозрачен фон. С фиксированным холстом — последний кадр, заново нарисованный в размере холста (`createFramePainter`).
- Символ ячейки разрешается по приоритету `charOverride → char → quantize(lum)`. Авторские `char` (из текстового импорта) учитываются только при включённом флаге `useSourceChars` — иначе смена рампы на текстовом источнике не давала бы никакого видимого результата. По умолчанию флаг включён.
- Ячейки с `alpha ≈ 0` или пустым символом в слое символов прозрачны — сквозь них виден фон.
- Правило выбора символа живёт в одной функции `resolveCellChar` (`render/cell-char.ts`); её используют рендер и все экспортёры, чтобы вывод совпадал с экраном.

### 9.2 Атлас глифов

- Маски покрытия, а не цветные тайлы: байт на физический пиксель, `cellW × cellH` на символ, растеризуются на canvas размером в одну ячейку и читаются `getImageData` один раз.
- Ключ кэша атласа: `(font, cellW, cellH)`; размер ячейки физический, поэтому `dpr` в него уже входит. Цвет в ключ не входит: одна маска служит любой теме.
- Ленивое пополнение: новый символ (например, из decode) растеризуется при первом появлении; массив масок растёт удвоением.
- Цвет на ячейку — палитра на ячейку поверх тех же масок (см. §9.1, цветной путь).

### 9.3 Процедурные блоки

Символы `░ ▒ ▓ █ ▀ ▄ ▌ ▐` рисуются в атлас не шрифтом, а прямоугольниками и узорами (тени — регулярная точечная маска плотностью 25%, 50%, 75%). Тайлы выровнены по целым пикселям, без щелей между ячейками. Оттенки зажигают ровно `round(d * w * h)` пикселей в порядке Bayer; фактическое покрытие любого блока на тайле `w × h` возвращает `blockGlyphDensity(code, w, h)`, и именно его использует измеритель (DECISIONS 010).

## 10. Цикл

- `requestAnimationFrame`, `dt` clamp до 1/20 с.
- Пауза при `document.hidden`.
- Порядок кадра: ввод → разрешение параметров → displace-выборка (или копия source→work) → cell → system.update/render → post (раскраска + красящие эффекты, DECISIONS 016) → renderer.
- Debug-оверлей: fps, время кадра по стадиям (`performance.now()`, в том числе `system`), число спрайтов (строка появляется, когда система их создала).

### 10.1 Транспорт (DECISIONS 023)

- Состояния: `playing` / `paused`. Часы транспорта — секунды с последнего «в начало» (`restart`); часы эффектов отсчитываются как раньше (с активации эффекта), «в начало» обнуляет и их.
- **Пауза** — время стоит: кадры идут с `dt = 0`, чтобы правки в панели (цвет, цепочка, холст) были видны сразу; курсор заморожен (`PointerInput.tick` не вызывается: события копятся в «сыром» состоянии и применяются раз в кадр), запись траектории курсора и `MediaRecorder` приостановлены. Оверлеи продолжают рисоваться.
- **Шаг** (только на паузе) — один кадр pipeline с `dt = 1/fps` (fps — из настроек видео), как в офлайн-рендере: кадр на паузе совпадает с кадром ролика в тот же момент.
- **В начало** — `restart` эффектов и трека; состояние воспроизведения сохраняется.
- **Запись** — та же, что во вкладке `export`; на паузе сначала включает воспроизведение.
- С треком часы кадра идут от слышимого звука (`AudioContext.getOutputTimestamp`, с учётом задержки вывода): `dt` = слышимое время транспорта − время кадра, в пределах `0…MAX_DT`. Если звук и кадр разошлись больше чем на 80 мс (`|<`, смена пресета, пропуск кадров), звук перематывается к часам транспорта. В скрытой вкладке звук останавливается вместе с кадрами. Код — `src/audio/` (`track.ts` — чистая математика позиции, `player.ts` — Web Audio, `slice.ts` — участок трека для рендера).
- **Перемотка** — ползунок в полосе транспорта: `restartAt(target − 10 с)` (часы ставятся сразу, без кадров: всё, что зависит только от времени, — точно), затем прогрев без отрисовки — крупными шагами до секунды перед целью и шагами `1/fps` последнюю секунду. Состояния эффектов с памятью (кольца ряби — жизнь до 10 с, переход курсора, проявление) восстанавливаются за прогрев; стоимость не зависит от того, куда перематывать (~260 кадров). Курсор на время прогрева считается ушедшим, экран держит последний кадр, звук молчит и потом догоняет. Будущим системам с долгой памятью (частицы) прогрев может понадобиться длиннее — решить в фазе 5. Длина ползунка — проход трека, без трека — 30 с, растёт с часами. Во время записи недоступна.
- UI: полоса внизу сцены поверх картинки, в кадр и экспорт не попадает. Клавиши: Home — в начало, Space — пауза, → — шаг, R — запись; в полях ввода не срабатывают.

## 11. Ввод

- Pointer events на canvas, координаты переводятся в ячейки (дробные); центр ячейки `(x, y)` — целые координаты, как у индексов эффектов. Вне canvas — `inside = false`.
- События только запоминают положение; скорость считается раз в кадр (`PointerInput.tick`) из смещения за кадр, поэтому затухает до нуля, когда курсор стоит. `clicked` гасит pipeline после кадра.
- Скорость курсора сглаживается экспоненциально, независимо от частоты кадров (постоянная времени 60 мс).
- Touch работает так же, как мышь.

## 12. Бюджет производительности

- 200×100 ячеек: ≤ 6 мс CPU на кадр без систем частиц, ≤ 10 мс с частицами (все непустые ячейки).
- 0 аллокаций за кадр в установившемся режиме. CPU-часть pipeline проверяется в Node: `node tests/bench/pipeline-perf.ts` (время) и счётчик сборок через `--trace-gc` (аллокации, DECISIONS 013); рендер — в DevTools Performance.
- Перед оптимизацией — замер. После — цифры до/после в отчёте.

## 12.1 Экспорт

- Текст: `exportText` поверх `resolveCellChar` — совпадает с экраном.
- Видео в реальном времени (`export/video-recorder.ts`): `canvas.captureStream(fps)` + `MediaRecorder`; с фиксированным холстом пишется отдельный холст W×H, в который каждый кадр копируется (с масштабом) экранный; формат — первый поддерживаемый из MP4/H.264, WebM/VP9, WebM/VP8; битрейт `пиксели · fps · {0.08, 0.15, 0.3}` (low/medium/high). Во время записи пишется траектория курсора (`export/pointer-track.ts`).
- Форматы у двух режимов свои (разные кодировщики): у записи — что умеет `MediaRecorder`, у рендера — MP4/H.264 или WebM/VP9, доступность проверяется под текущие размер, fps и битрейт (`probeOfflineFormats` → `ok` / `size` / `none`: эталон 1280×720 @ 30 fps отличает «не тянет параметры» от «нет кодировщика»); недоступный формат виден в списке с пометкой и причиной, подмены другим форматом нет.
- Офлайн-рендер (`export/offline-render.ts`, DECISIONS 017): отдельный pipeline и холст целевого размера — размер холста, а при `auto` — из списка (`screen`, 1080×1080, 1080×1350, 1080×1920, 1920×1080); сетка вписана по центру (`layoutFrame`), шаг ровно `1/fps`. Длительность — явная: как последняя запись (`take`, без записи 10 с) или 5–30 с. Курсор из последней записи или отсутствует; после конца записи курсор «уходит» (`inside = false`). WebCodecs + mediabunny, формат выбирается явно.
- Холст рендера всегда чётного размера в физических пикселях (дополняется пикселем фона).
- Прозрачность (DECISIONS 020): при фоне `transparent` офлайн-рендер в WebM/VP9 кодирует альфу (`alpha: 'keep'`, `alpha_mode=1`); MP4/H.264 альфу не несёт — в обоих списках форматов он помечен «no transparency», выбор не подменяется. Живая запись в WebM (`MediaRecorder`, Chrome) тоже сохраняет альфу — проверено пользователем.

- **Звук** (DECISIONS 023): живая запись — поток холста плюс дорожка из `MediaStreamAudioDestinationNode`, формат записи с аудиокодеком: WebM — `opus`; MP4 — `mp4a.40.2` (AAC), а если его нет — `opus` (MediaRecorder в Chrome так умеет); без аудиокодека — пометка «no audio». Дорожка записи берётся до `mute`. Офлайн-рендер — `AudioBufferSource` mediabunny с участком трека `[offset, offset + длительность]` (с повтором при `loop`): Opus в WebM, AAC в MP4; доступность — `canEncodeAudio`, при отсутствии кодировщика формат помечается «no audio», подмены нет. Длительность рендера `audio` — по треку от `offset`.

## 13. Каталог эффектов (начальный)

**Cell**
- `wave` — синусоидальная волна по яркости (направление, длина, скорость, амплитуда).
- `erosion` — шумовой порог: ячейка гаснет, если `noise(x, y, t) < threshold`; порог анимируемый.
- `decode` — «расшифровка»: символы перебирают случайные варианты и фиксируются на правильном; фронт расходится от точки (`center`, `speed`, `scrambleSet`).
- `pulse` — пульсация яркости/контраста от точки или глобально.
- `posterize` — сокращение числа уровней яркости.
- `edge-glow` — подсветка по модулю градиента, бегущий «ток» по контурам.

**Displace**
- `ripple` — круговые волны от точки/курсора (амплитуда, длина волны, скорость, затухание).
- `swirl` — закручивание вокруг точки.
- `lens` — линза под курсором (увеличение/уменьшение).
- `liquid` — смещение потоком шума.
- `glitch-rows` — случайные горизонтальные сдвиги полос строк.
- `shake` — дрожание.

**System**
- `particles` — каждая ячейка — частица с домашней позицией и пружиной; координаты изотропные (в ширинах ячейки по обеим осям). Сдвинутая частица — спрайт, в покое (ближе 0.02 и медленнее 0.05) — снова ячейка. Чанк 1: `spring`, `damping`, взрыв по клику (`click force`, `click radius`), `snap to cells`. Дальше: отталкивание курсором, взрыв по удару трека, сборка из хаоса на старте (`intro`).
- `trails` — feedback: кадр смешивается с предыдущим с затуханием.
- `sand` — символы осыпаются под гравитацией и копятся (клеточный автомат), с возвратом по таймеру или клику.
