## Контекст

Ролики для соцсетей. Два режима: запись в реальном времени (что на экране, с курсором) и офлайн-рендер кадр за кадром (ровный fps, размер под площадку). Кадр детерминирован (DECISIONS 012), поэтому офлайн-рендер может повторить запись при той же траектории курсора. Каждый чанк заканчивается зелёным `npm run check` и отметкой здесь.

## Отчёт исполнителя

**Чанк 1.** `export/video-recorder.ts`: `supportedFormats` (MP4/H.264 в приоритете, WebM как запасной, по одному на контейнер), `bitrateFor` (0.08/0.15/0.3 бита на пиксель для low/medium/high — тексту нужно намного больше, чем фильму), `videoFileName` (`источник-пресет.mp4`), `CanvasRecorder` (`captureStream(fps)` + `MediaRecorder`, данные кусками раз в секунду). Панель: секция `video` — формат, fps 60/30, качество, длительность (вручную, 5/10/15/30 с), «from start» (перезапуск эффектов в момент старта), кнопка записи с таймером; файл скачивается сам, размер — в строке статуса. Во время записи вокруг сцены красная рамка (не на canvas, в ролик не попадает). Холст дополняется до чётных размеров пикселем фона: H.264 не кодирует нечётные. Тестов: 238 → 242.

**Чанк 2.** `export/pointer-track.ts`: `PointerTrack` — сэмпл на кадр (время pipeline, x, y, флаги inside/down/click) в растущих typed arrays; `apply(time, prevTime, out)` — позиция интерполируется, скорость из позиций на концах окна, клик срабатывает ровно в том кадре, чьё окно `(prevTime, time]` его содержит (не теряется при более редких кадрах). `main.ts` пишет траекторию во время записи видео, время — относительно старта записи. Тестов: 242 → 247.

**Чанк 3.** Пользователь выбрал mediabunny; поставлена `1.61.3`, версия закреплена точно. `export/mux.ts` — именованные реэкспорты (tree-shaking: 695 → 218 КБ, 57 КБ gzip), грузится динамическим импортом только при рендере; основной бандл не изменился (79 КБ). `export/offline-render.ts`: `layoutFrame` (самая крупная ячейка с верным аспектом, сетка по центру на чётных отступах), `renderOffline` — свой pipeline (та же цепочка, цвет, сид), свой холст целевого размера, рампа перемеряется под новую ячейку, шаг ровно `1/fps`, курсор из `PointerTrack`, кодирование H.264/MP4 (или VP9/WebM, если H.264 не кодируется), отмена через `AbortSignal`. Панель: размер (`screen`, 1080×1080, 1080×1350, 1080×1920, 1920×1080), «replay take» (воспроизвести курсор последней записи; длительность — длительность записи), кнопка `render` с процентами и отменой. Без записи длительность берётся из `length` (или 10 с), курсора в кадре нет. Тестов: 247 → 252.

**Чанк 4.** DECISIONS 017, SPEC §12.1, ROADMAP (пункт экспорта фазы 6), стек в `AGENTS.md` (зависимость и правило её подключения).

### Что проверить в браузере

1. **Запись.** Пресет с курсором (Liquid portrait), `length` 10 s, `from start` — `● record`, поводить курсором. Красная рамка вокруг сцены, таймер на кнопке, через 10 с файл скачивается. В статусе — имя и размер.
2. Файл открывается в плеере. Проверить: MP4 (в Chrome) и что мелкий текст читается при `quality: high`.
3. **Офлайн.** Сразу после записи: `size` 1080×1080, `replay take` включён, `render` — проценты на кнопке, файл 1080×1080 той же длительности, движения курсора повторяют запись, кадры ровные. `cancel` во время рендера останавливает его, статус «render cancelled».
4. `size` 1080×1920 на горизонтальной картинке — сетка по центру, поля цвета фона.
5. Цветной пресет (Neon tide) — цвета в ролике те же, что на экране.
6. Во время записи не менять размер окна и `cols` — поведение `MediaRecorder` при смене размера холста зависит от браузера (сказать, если ломается).
7. Загрузить файл в Telegram или Instagram — принимается (MP4/H.264).
