## Отчёт исполнителя

**Чанк 1.** `core/prng.ts`: `createRand` (mulberry32), `hash2`/`hash3` для стабильной поячеечной случайности. `params.ts`: `ParamInput`, `ParamBag`, `createParamBag`, `resolveParams` (без аллокаций, точки мутируют свой `Vec2`), числа клампятся; LFO/env пока дают default. `effects/types.ts`: `defineEffect` + `AnyEffectDef`. `pipeline/pipeline.ts`: класс `Pipeline` — цепочка, `frame(dt)` (clamp dt, разрешение параметров, копия source→work, cell-стадия через один `CellRef`, тайминги по стадиям), `setSource`/`restart` пересоздают экземпляры (DECISIONS 012), `clicked` гасится после кадра. SPEC §6, §6.2, §7. Тестов: 77 → 92.

**Чанк 2.** `core/loop.ts` (rAF, пауза при `document.hidden`, первый кадр после паузы с `dt = 0`). `core/pointer.ts`: `PointerInput` (pointer events, capture, touch без hover), `clientToCell`, `smoothToward`. `ui/debug-overlay.ts`: fps и мс по стадиям `params/copy/cell/render/total`, сглаживание 0.5 с, DOM обновляется 4 раза в секунду. `main.ts` разделён на `rebuild()` (файл, настройки, resize) и `frame(dt)` (каждый кадр); pipeline пересоздаёт эффекты, только если сменилось само поле; текстовое поле кэшируется по (рампа, полярность). Галочка `debug` в панели. Тестов: 92 → 95.

**Чанк 3.** `effects/cell/wave.ts` — эталон: живые параметры, кэш вектора направления, изотропное расстояние в ширинах ячейки. `effects/cell/decode.ts`: фронт от `center` (изотропный), до фронта ячейка скрыта (`hideBefore`), затем `scramble` секунд случайных символов из набора (`ascii/binary/hex/blocks`, через `hash3` по такту `rate`), потом `charOverride = 0`; задержка по ячейкам `jitter` через `hash2`; пустые ячейки не трогает. `effects/builtin.ts` регистрирует оба. `ui/controls.ts` — контролы из схемы (number/boolean/select/color; point — только `center`/`pointer`). В панели секция `effects`: галочка + параметры, кнопка `restart`. Включение эффекта пересоздаёт экземпляр (дополнено DECISIONS 012). `Pipeline.add` больше не копирует `values` — ими владеет вызывающий. Тестов: 95 → 104.

**Чанк 4.** `core/noise.ts`: `createNoise(seed)` — simplex 2D/3D по Густавсону, `fbm2`/`fbm3` с нормировкой в −1..1, таблицы на сид, выборка без аллокаций. `erosion`: fbm3 по (x, y/aspect, t·speed), порог со сглаженным краем (`threshold − softness … threshold`; 0 — всё на месте, 1 — всё стёрто), режимы `hide` (alpha) и `darken` (lum). `pulse`: `global` или `radial` (кольца от `center`, затухание `exp(−d/radius)`), цель — яркость или контраст вокруг 0.5. Тестов: 104 → 124.

**Чанк 5.** `tests/bench/pipeline-perf.ts` (Node 24 запускает TS напрямую; bench-API vitest 5 изменился, не стал с ним возиться). Замер показал аллокации в `erosion`: V8 упаковывал дробные аргументы невстроенного ядра simplex. Ядра переведены на ввод/вывод через `Float64Array` (DECISIONS 013, пометка в инварианте 4 `AGENTS.md`).

### Что проверить в браузере

1. Загрузить фото с `cols` = 200. В оверлее `render` и `total` при выключенных эффектах; затем по одному эффекту; затем все четыре. Нужны цифры `render`/`total` и fps.
2. `wave`: полосы бегут плавно, направление 45° идёт по диагонали экрана (а не сплющено).
3. `pulse`: кольца от курсора круглые, не эллипсы; при уходе курсора с canvas центр остаётся на последнем месте.
4. `erosion`: дыры плавно «текут», края мягкие; `darken` гасит без исчезновения.
5. `decode`: при включении фронт расходится из центра, символы мерцают и встают на место; `restart` и повторное включение проигрывают заново; при загрузке другой картинки — тоже.
6. Смена рампы/полярности во время анимации не сбрасывает эффекты (на фото); вкладка в фоне — цикл стоит, при возврате нет рывка.
7. Консоль без ошибок; DevTools Performance — нет регулярных Minor GC при работающих эффектах.

## Ревью

Саморевью архитектора. Визуальная приёмка и замер пройдены пользователем; превышение бюджета цепочкой из четырёх эффектов принято (см. итог).


**Чанк 6.** Замер в браузере на 200×110, ячейка 6×11, все четыре эффекта: `cell` 4.9 мс, `render` 20.3 мс, `total` 25.2 мс, 34 fps. `drawImage` на ячейку упирается в стоимость вызова Canvas API.

- `render/compositor.ts` — чистый композитор: маска × квантованная alpha → палитра фон→символ, запись в `Uint32Array` поверх буфера `ImageData`, пропуск ячеек без изменений, полоса грязных строк.
- `render/atlas.ts` — атлас масок покрытия (байт на пиксель, растеризация в canvas на одну ячейку, без цвета в ключе).
- `render/canvas2d.ts` — `putImageData` грязной полосы; палитра пересобирается при смене темы, атлас — при смене размера/шрифта.
- `decode` давал аллокации в цепочке из четырёх эффектов (хеш возвращал дробное число из невстроенного вызова): `hashInt2/hashInt3` возвращают целые < 2^24.
- DECISIONS 014 (решение 003 в части рендера заменено), SPEC §9.1–9.2.

Композиция кадра в Node (`node tests/bench/render-perf.ts`), медиана / p95, мс:

| ячейка | статичный | wave | erosion | все четыре |
|---|---|---|---|---|
| 6×11 | 0.32 / 0.35 | 0.54 / 0.63 | 0.74 / 0.83 | 0.92 / 1.92 |
| 12×22 (dpr 2) | 0.37 / 0.40 | 1.01 / 1.27 | 1.52 / 1.67 | 1.99 / 6.82 |

До — 20.3 мс в браузере (`drawImage`); после — ~1 мс композиции плюс `putImageData`, который мерится только в браузере. Сборок мусора за кадр нет ни в pipeline, ни в композиции. Тестов: 124 → 131.

Проверить в браузере: тот же сценарий (200 cols, все четыре эффекта) — цифры `render`/`total`/fps; символы выглядят так же, как до замены (сглаживание, блоки без щелей, прозрачность при `erosion`); смена полярности перекрашивает сразу.

**Итог в браузере** (пользователь, 200×110, ячейка 6×11, все четыре эффекта): 60 fps; `cell` 6.56 мс, `render` 1.56 мс (было 20.3), `total` 8.16 мс (было 25.2).

Бюджет SPEC §12 (≤ 6 мс) выполнен для одного-двух эффектов; цепочка из всех четырёх превышает его на ~2 мс за счёт cell-стадии (в браузере она в ~1.5 раза медленнее, чем в Node), при этом держит 60 fps. Резерв, если понадобится: шум `erosion` на сетке пониже с интерполяцией, кэш расстояний в `pulse`/`decode` при неподвижном центре.
