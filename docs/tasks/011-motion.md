## Отчёт исполнителя

**Чанки 1–3.** `pipeline/points.ts`: `PathSpec` (orbit, lissajous, wander, sweep, bounce, path), `MotionValue` (`axes`, `path`, `follow`), `evalPath` — функция времени эффекта без состояния, `resolveMotion` (оси через существующие источники модуляции; `follow` — смешивание курсора и `idle` с весом в `PointState.w`, плавность `ease`, сброс при обратном ходе часов), `isPathSpec` / `isMotionValue` для валидации. `PointValue` расширен, точка в мешке параметров — `PointState` (координаты + состояние перехода), `ParamFrame` = `PointFrame` (с `cellAspect` и `pointer.inside`), `resolvePoint(value, frame, t, out)`; центр маски `radial` получил движение бесплатно. Пресеты валидируют движущиеся точки. Отступление от SPEC §7.1: размеры траекторий — в долях ширины картинки, а не в ширинах ячейки (пресет выглядит одинаково при любых `cols`; изотропность сохранена), SPEC и DECISIONS 018 обновлены. Тестов: 279 → 295.

Под «реестром источников точки» в постановке подразумевалась расширяемость; реализована как закрытый набор форм `MotionValue` и видов `PathSpec` с одной точкой расширения (`evalPath` / `isPathSpec`): отдельный реестр сейчас дал бы лишний слой без второго пользователя. MIDI X/Y-пэд (фаза 4.5) добавится новой формой `MotionValue`.

**Чанк 4.** `ui/point-control.ts` вместо прежнего контрола точки: режим `position / cursor / axes / orbit / lissajous / wander / sweep / bounce / path`; у позиции и центров траекторий — сетка 3×3 с ползунками `x`/`y`; у осей — два числовых контрола с `const / lfo / env`; у курсора — `when away` (`stay`, позиция или любая траектория) и `handover, s`; у `path` — точки текстом `t:x:y`. При смене режима траектория строится от текущей позиции (`defaultPath`, медленные скорости). Тот же контрол у центра маски `radial`. `Pipeline.forEachCenter` + `ui/centers-overlay.ts`: при `debug` над картинкой крестики центров эффектов и кольца радиальных масок с подписями (отдельный холст, в кадр не попадает). Тестов: 295 → 303.
