# Roadmap

Работаем строго по фазам. Каждая фаза заканчивается зелёным `npm run check`, отчётом и списком того, что проверить в браузере. Отметки `[x]` ставит агент по мере выполнения.

## Фаза 0 — Каркас

- [x] Очистить демо-код шаблона Vite (`counter.ts`, стили, лого).
- [x] `tsconfig`: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `exactOptionalPropertyTypes`.
- [x] Скрипты: `check` (`tsc --noEmit && vitest run`), `test` (`vitest`).
- [x] Конфиг vitest (environment `node`; тесты, которым нужен canvas, пока не пишем — логику держим в чистых функциях).
- [x] Структура папок из `CLAUDE.md`, модули с экспортом типов из SPEC.
- [x] `index.html`: полноэкранный контейнер с canvas, место под панель.

**Готово, когда:** `npm run check` и `npm run build` проходят; страница открывается без ошибок в консоли.

- [x] Тесты: квантование, обратный поиск по рампе, импорт текста (выравнивание, табы), Собель на синтетическом поле.

**Готово, когда:** загруженная фотография отображается как ASCII; смена рампы и полярности мгновенно перерисовывает картинку; блоки `░▒▓█` стыкуются без щелей; картинка не растянута по вертикали.

## Фаза 4.7 — Слои, прозрачность, подложка (до движения центров, MIDI и частиц)

Решение — DECISIONS 020. Порядок шагов важен: шаг 1 — фундамент для остальных и для частиц (фаза 5).

**Шаг 0 — разведка (до кода)**
- [x] Пробный WebM/VP9 с альфой через WebCodecs в Chrome пользователя. Итог: кодируется, `alpha_mode=1`; OpenReel (десктоп) накладывает с прозрачностью и мягкими краями; мобильный CapCut альфу не читает — ориентир OpenReel.

**Шаг 1 — двухслойный рендер**
- [x] Символы рисуются в отдельный прозрачный слой (палитра на ячейку и пропуск неизменившихся ячеек сохраняются); основной холст = фон + слой символов (`drawImage`).
- [x] Фон: цвет темы, свой цвет (в том числе ключевой для хромакея), прозрачный.
- [x] Запись и офлайн-рендер получают итоговую картинку. Замер до/после.
- [x] Экспорт кадра в PNG (с альфой при прозрачном фоне).

**Шаг 2 — прозрачное видео**
- [x] WebM/VP9 с альфой (подтверждено шагом 0). PNG-последовательность не делаем.

**Шаг 3 — картинка-подложка**
- [x] Загрузка отдельного изображения; вписывание (cover / contain / stretch), непрозрачность, затемнение, размытие; «исходное фото как фон».
- [x] Работает в записи и офлайн-рендере. В пресете хранятся только настройки фона, сама картинка — нет.

**Шаг 4 — плашки ячеек**
- [x] Канал фона ячейки (RGB + непрозрачность) в рабочем буфере и `CellRef`; режимы `none / source / gradient`; `mix` и маски; палитра «символ поверх плашки».
- [x] Эффект `glow` (подсветка плашек), пресеты «растворение в фото» и «цветные плашки».

**Готово, когда:** символы можно положить поверх своей картинки или прозрачного фона; `erosion`/`decode`/маски открывают подложку; ролик с подложкой пишется и рендерится офлайн; есть экспорт с прозрачностью, который принимает монтажный редактор.

## Фаза 4.6 — Позиции и движение центров

Спецификация — SPEC §7.1, решение — DECISIONS 018. Два коммита.

**Коммит 1 — позиции**
- [x] Контрол точки: сетка 3×3, кнопка «курсор», ползунки `x`/`y`.
- [x] Диапазон позиции −0.5…1.5 в разрешении, валидации пресетов и UI.
- [x] Генератор `random` выбирает и позиции, не только центр и курсор.

**Коммит 2 — движение**
- [x] Реестр источников точки; режим «по осям» (`ParamValue` на каждой оси).
- [x] Траектории: `orbit`, `lissajous`, `wander`, `sweep`, `bounce`, `path` — изотропно.
- [x] Курсор с автоматикой: `follow: 'pointer'` + `idle`, плавные переходы; только явное включение, встроенные пресеты с `pointer` не меняются.
- [x] Валидация в пресетах, редактор в панели, центры на debug-оверлее.
- [x] Пара новых пресетов с движением; раздел в `PRESETS.md`.
- [x] Тесты: изотропность орбиты, детерминизм по времени, переходы курсор ↔ траектория, валидация.

**Готово, когда:** любой центр можно поставить в одну из девяти позиций или произвольно (в том числе за краем); центр может двигаться сам по траектории или по LFO на осях; курсор с автоматикой плавно перехватывает и отдаёт управление; офлайн-рендер повторяет движение.

## Фаза 4.8 — Транспорт и звук (до MIDI и частиц)

Спецификация — SPEC §7.2, §10.1, §12.1; решение — DECISIONS 023. MIDI (4.5) потом ложится на готовые источники и триггеры.

**Чанк 1 — транспорт**
- [x] Полоса внизу сцены (оверлей, в кадр не попадает): `|<` в начало, `▶ / ⏸`, `>|` шаг на кадр (на паузе), `●` запись, счётчик времени.
- [x] Пауза = время стоит (кадры с `dt = 0`, правки панели видны), курсор картинку не трогает. Шаг — один кадр с шагом `1/fps`, как в офлайн-рендере.
- [x] Клавиши: Home, Space, →, R (не срабатывают в полях ввода).

**Чанк 2 — трек**
- [x] Загрузка аудиофайла (сессия, в пресет не попадает), сдвиг начала, повтор; проигрывание синхронно с транспортом, часы кадра идут от часов звука.
- [x] Экспорт со звуком: живая запись (`MediaRecorder`, звук из Web Audio) и офлайн-рендер (mediabunny: Opus в WebM, AAC в MP4); проба кодировщика, без подмены.
- [x] Длительность рендера `audio` — по треку.

**Чанк 3 — источник модуляции `audio`**
- [x] Таблица полос (`level`, `bass`, `mid`, `high`) по треку при загрузке: своё БПФ, шаг 10 мс, нормировка по треку.
- [x] `{ audio: band, min, max, gain?, attack?, release? }` в реестре модуляции; сглаживание без состояния — от таблицы. Без трека — `min`.
- [x] Редактор в панели, тесты БПФ, полос и детерминизма (экран = офлайн).

**Чанк 4 — перемотка и триггеры**
- [x] Полоса времени с перемоткой: быстрый прогон pipeline от нуля без отрисовки.
- [x] Удары трека (onset) как триггеры: клик-эквивалент (`ripple` click, перезапуск огибающих); общий механизм с нотами MIDI.
- [x] Пресет «под музыку», руководство, `PRESETS.md`.

**Готово, когда:** транспортом можно остановить, пройти по кадрам и записать; трек играет в такт эффектам и попадает в запись и рендер; параметр «дышит» от баса одинаково на экране и в ролике; удар трека запускает кольцо ряби.

## Фаза 5 — Системы

- [x] Пул спрайтов в WorkBuffer и их рендер.
- [x] `particles` (пружина к дому, отталкивание, взрыв по клику и удару трека, intro-сборка).
- [x] `trails` (эхо сетки и хвосты у летящих символов).
- [x] `sand` (осыпание и возврат).
- [x] Замеры производительности с частицами на 200×100 (браузерный стенд, DECISIONS 027).

**Готово, когда:** частицы держат 60 fps на целевом размере; взрыв и сборка выглядят плавно; системы корректно переинициализируются при смене картинки.

## Фаза 6 — Полировка (по согласованию)

- [ ] Переходы между двумя полотнами (по яркости и через частицы).
- [ ] Рампа как параметр эффекта в маске — войдёт в операции поля (фаза 6.2).
- [x] Цветной режим: `mono` / `source` / `gradient`, красящие эффекты `tint` и `hue-cycle` (задача 008; вместо квантованной палитры — палитра на ячейку, DECISIONS 014–016).
- [x] Экспорт видео: запись в реальном времени (`MediaRecorder`, MP4/WebM) и офлайн-рендер с ровным fps и размерами под соцсети (задача 009). Экспорт кадра в PNG — сделан в фазе 4.7.
- [x] Экспорт кадра в текст (`.txt`): символы по тому же приоритету, что в рендере (`charOverride → char → quantize`), пустые ячейки — пробелы. Опции: копировать в буфер обмена, обрезать хвостовые пробелы. Спрайты систем не попадают в сетку — решить при постановке. Взята раньше фазы: задача 003.
- [ ] Встраиваемый API: `mount(element, { source, preset })` без панели.
- [ ] Тюнинг эффектов и пресетов — разбит на фазы 6.1–6.4 ниже. Отдельно: производительность — pipeline `Liquid portrait` в браузере 6.4 мс, чуть выше бюджета §12 (6 мс), главный вклад — шум `liquid`.
- [ ] Медиа для документации: главный ролик для README, кадры и короткие ролики к разделам руководства (отложено из задачи 014, чанк 6).

## Фаза 6.1 — Музыкальность без магии

Решение — DECISIONS 028, спецификация — SPEC §7.3.

- [x] Удалить удары-триггеры: `ripple` `beat`, `beat force` у `particles`, `beat radius` у `sand`, огибающая `on beat`, `FrameContext.beat`, `findOnsets`.
- [x] Явная сила в точке: у `particles` — радиальный толчок из `center` (сила, радиус), у `sand` — осыпание в круге вокруг `center` (темп, радиус).
- [x] Модуляция «шаг по звуку» для чисел (`random` / `cycle` / `add`, порог, гистерезис, `glide`) и точек (`random` в области / `grid` 3×3 / `list`); без состояния, по таблице полос.
- [x] Индикаторы полос и порога в секции `audio`.
- [x] Пресеты Beat drop и Beat burst — на новом подходе (например: центр толчка на «шаге по басу», сила на `audio bass`, хвосты `trails`).
- [x] Руководство, `PRESETS.md`, тесты детерминизма.

**Готово, когда:** в панели нет скрытых ударов; взрыв на каждой бочке в новом месте собирается из обычных параметров и одинаков на экране и в ролике; индикаторы показывают, что движет эффектами.

## Фаза 6.2 — Поле + операция

Решение — DECISIONS 029.

- [ ] Фундамент: поля (круг, кольцо, квадрат, полосы, сетка, шахматка, вращающаяся линия, плазма) с движением через обычные параметры; операции (инвертировать, залить, стереть, сменить рампу, сдвиг яркости, дизер), жёсткий край по умолчанию.
- [ ] Смена рампы на ячейку — решение о контракте (через `charOverride` или расширение квантователя) с записью в DECISIONS.
- [ ] 3–4 эффекта-образца (например: полосы-инверсия, расходящиеся кольца с заливкой, вращающаяся линия со сменой рампы, плазма-дизер).
- [ ] Замер на стенде, руководство.

## Фаза 6.3 — Бриф эффекта и каталог

- [ ] Шаблон-бриф задачи на эффект (идея, референс, что видно, параметры и интересные диапазоны, что отдать звуку и движению, тест, критерий «как выглядит»); скил `/new-effect` под него.
- [ ] Эффекты на поле + операции по брифам.
- [ ] Сценарные системы по образцу `sand`: жизнь, «матричный» дождь, сортировка символов, перетасовка блоков, калейдоскоп, крупные «пиксели», печатная машинка, сканирующая строка — по согласованию, по одной.

## Фаза 6.4 — Пересборка пресетов

- [ ] Пресеты «сценарные», а не «тряска и скручивание»: на полях, операциях, системах и явной музыкальности. Ревизия старых: что оставить, что заменить.

## Фаза 4.5 — WebMIDI (отложена в конец по решению пользователя)

- [ ] Источник модуляции `midi` (CC, канал, диапазон) в реестре источников фазы 4; без зависимостей, Web MIDI API.
- [ ] «Выучить ручку»: у числового параметра режим ожидания первого пришедшего CC.
- [ ] Ноты как триггеры: клик-эквивалент (`ripple` click, перезапуск огибающих), скорость нажатия → амплитуда. Механизм триггеров — общий с ударами трека (фаза 4.8).
- [ ] Привязки сохраняются в пресете; без MIDI-устройства пресет работает (значение по умолчанию).

**Готово, когда:** ручка контроллера плавно управляет любым числовым параметром, нота запускает кольцо ряби; пресет с MIDI-привязками грузится и без устройства.
