# ASCII Engine — общие правила для всех агентов

Этот файл читают все агенты в репозитории (Codex напрямую, Claude Code через импорт в `CLAUDE.md`). Роли агентов описаны в их собственных конфигах; здесь только то, что одинаково для всех.

Браузерный движок ASCII-анимации. Исходник — изображение (или готовый ASCII-текст), которое переводится в поле яркостей. Эффекты — параметризуемые функции-пресеты — анимируют поле каждый кадр. Символы выбираются по рампе в самом конце, рендер — Canvas 2D с атласом глифов.

Источники правды:
- `docs/SPEC.md` — архитектура и контракты;
- `docs/ROADMAP.md` — фазы и критерии готовности;
- `docs/DECISIONS.md` — принятые архитектурные решения и их причины;
- `docs/tasks/` — конкретные задачи с критериями приёмки;
- `docs/OPEN-QUESTIONS.md` — вопросы, которые исполнитель не вправе решать сам.
- `docs/PRESETS.md` — справочник для подбора пресетов (эффекты, диапазоны, приёмы).

## Стек

- Vite + TypeScript, шаблон `vanilla-ts`, `strict: true`, `noUncheckedIndexedAccess: true`.
- Без UI-фреймворков. Единственная рантайм-зависимость — `mediabunny` (муксер видео, DECISIONS 017), только через `src/export/mux.ts` и динамический импорт. Dev-зависимость: `vitest`.
- Новые зависимости — только после согласования с пользователем.
- Шум, PRNG, математику пишем сами (небольшие модули в `src/core/`).

## Команды

- `npm run check` — `tsc --noEmit` + `vitest run`. Обязательно перед завершением любой задачи.
- `npm run build` — продакшн-сборка.
- `npx vitest run <путь>` — точечный прогон тестов.
- `npm run dev` и `npm run test` — **не запускать**: это блокирующие процессы. Dev-сервер держит пользователь. Для визуальной проверки опиши, что открыть и на что смотреть.

## Инварианты (не нарушать без записи в DECISIONS.md)

1. **Источник неизменяем.** Эффекты пишут только в рабочий буфер.
2. **Эффекты работают с яркостью, а не с символами.** Символ выбирается квантованием по рампе в конце. Исключение — эффекты, явно выставляющие `char`-override (например, decode).
3. **`lum` — яркость изображения**, 0 = чёрный, 1 = белый. Полярность (`light-on-dark` / `dark-on-light`) учитывается только на границах между яркостью и символами: в квантователе (яркость → символ на выводе) и в импорте текста (символ → яркость на вводе). Больше нигде; эффекты про полярность не знают.
4. **Никаких аллокаций в горячем цикле** (на ячейку и на кадр в установившемся режиме): typed arrays, переиспользуемые scratch-объекты, out-параметры. Неочевидный случай: дробное число, переданное в большую (невстраиваемую) функцию или возвращённое из неё, упаковывается V8 в объект — см. DECISIONS 013 и `tests/bench/pipeline-perf.ts`. Целые в пределах 2^30 не упаковываются: хеши (`hashInt2/3`) принимают и возвращают целые. В горячем цикле не смешивай целую константу и double в одном тернарнике — используй `Math.min/max`.
5. **Координаты эффектов — в ячейках.** Для изотропных вещей (круги, расстояния, скорости) учитывай `ctx.cellAspect`.
6. **Эффект — это дескриптор** (id, тип, схема параметров, фабрика), зарегистрированный в `registry`. UI строится из схемы автоматически.
7. **Эффекты не знают про LFO.** Движок каждый кадр разрешает параметры в обычные числа.
8. **Чистые функции покрыты тестами**: рампа, квантование, сэмплинг, LFO/огибающие, импорт, валидация пресетов, cell- и displace-эффекты на маленьких полях.

## Стиль кода

- Без `any`. `!` для обхода `noUncheckedIndexedAccess` — только в горячих циклах и с комментарием.
- Файлы в kebab-case, типы в PascalCase, функции в camelCase.
- Комментарии в коде на английском, коротко.
- Маленькие модули. Один эффект — один файл. Только именованные экспорты.

## Задачи (`docs/tasks/`)

Файл задачи: `docs/tasks/NNN-slug.md` по шаблону `docs/tasks/_TEMPLATE.md`. Поле `Статус` в шапке:

- `ready` — задача сформулирована, можно брать;
- `in-progress` — кто-то взял (указать исполнителя);
- `review` — сделано, ждёт ревью;
- `done` — принято;
- `blocked` — нужен ответ, вопрос записан в `docs/OPEN-QUESTIONS.md`.

Исполнитель пишет отчёт в раздел «Отчёт исполнителя» того же файла и не трогает разделы постановки.

## Общие правила завершения задачи

1. `npm run check` проходит.
2. Отчёт: что сделано, отклонения от постановки и почему.
3. Что проверить в браузере — конкретно.
4. Предложенное сообщение коммита (Conventional Commits). **Агенты не коммитят и не пушат.**
5. Если затронут контракт из `SPEC.md` — это не задача исполнителя; см. правила роли.
